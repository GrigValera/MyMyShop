# Безопасность и границы доверия

Здесь описаны текущие ограничения и будущая ответственность. Backend проверяет app-owned server-side session для demo actor; внешняя identity integration отсутствует. Документ не заявляет о наличии production-контролей или сертификатов.

**SHOP-AUTH-SESSION-02 — CURRENT:** публичные demo email и пароль проверяются backend через отдельный scrypt verifier с salt и timing-safe comparison; SQLite не хранит пароль в открытом виде. Неверные данные возвращают одинаковый `401 invalid_credentials`. В production demo-проверка выключена. Cookie содержит 32 случайных байта в base64url, выставляется с `HttpOnly`, `SameSite=Lax`, `Path=/` и без `Domain`. Для HTTPS используется `Secure` и `__Host-` имя; loopback HTTP development использует отдельное имя. SQLite хранит только SHA-256 токена, actor, creation/expiry; срок фиксирован на семь суток. Повторный вход выдаёт новый токен и удаляет текущую сессию, logout удаляет запись. `POST /session`, `DELETE /session` и authenticated `PATCH /me` проверяют Origin против `PUBLIC_ORIGIN`; credentialed wildcard CORS не включён. API не логирует cookie, token, hash или request body. Истёкшая/неверная cookie не даёт actor. Защита от XSS остаётся критичной: захват браузерной сессии всё ещё позволяет выполнять запросы до истечения или logout. Перед открытым public demo нужна защита от перебора пароля и злоупотребления созданием sessions.

**CURRENT — ограничение:** `cartPersistence` проверяет форму и отбрасывает повреждённые данные, но не делает значения браузера достоверными. Настоящее оформление не может брать из него итоговую цену или наличие. Запись контактной формы в console — ограничение приватности и UX для следующего ticket поддержки, а не работающая отправка обращения. Статический demo на GitHub Pages не даёт серверной границы безопасности.

**PLANNED — открытые решения:** внешний источник identity, восстановление доступа, правила Customer authorization, проверка callbacks поставщика, аудит платежей/возвратов, хранение персональных данных, обработка вложений/аватара, секреты и заголовки развёртывания. При cross-origin размещении отдельно пересмотреть cookie и CSRF. Сертификация PCI, GDPR или иная не заявляется.
