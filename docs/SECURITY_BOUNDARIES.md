# Безопасность и границы доверия

Здесь описаны текущие ограничения и будущая ответственность. Минимальный backend foundation проверяет только локального development/test actor и не является настоящей аутентификацией. Документ не заявляет о наличии production-контролей или сертификатов.

| Граница | CURRENT | Правило PLANNED / PROPOSED |
| --- | --- | --- |
| Состояние браузера | Redux и `localStorage` изменяемы; корзина содержит данные для отображения; demo-сессия не даёт доступа | Не доверять цене/итогу корзины, утверждениям сессии и ролям; чувствительные операции проверяет backend |
| Идентификация/права | Frontend `demoSessionAdapter` работает только в памяти; backend `/me` допускает фиксированного test actor лишь в development/test при явном флаге и loopback host | Настоящий backend управляет идентичностью, сессией, ролями, защищёнными данными Customer и решениями о доступе |
| Заказы/деньги | Реальных Order, Payment и Refund нет | Backend владеет статусом заказа, проверкой цены/наличия, связью с оплатой и решениями о возврате |
| Внешние системы | В дополнительном режиме каталог читает только публичный DummyJSON | Credentials интеграций остаются на сервере; прямого доступа браузера к backend API CRM/ERP/WMS/перевозчика/PSP нет |
| Защищённый UI платежного поставщика | Нет | Возможен узкий сценарий компонента/перенаправления поставщика; достоверный результат проверяет backend |
| Персональные данные | Demo-профиль редактируется только в памяти runtime: email read-only, локальный аватар без серверной загрузки; контактная форма сейчас пишет введённое в console | Профиль, адреса, заказы, поддержка и аватар требуют контроля доступа, минимизации, сроков хранения и безопасных журналов |

**CURRENT — ограничение:** `cartPersistence` проверяет форму и отбрасывает повреждённые данные, но не делает значения браузера достоверными. Настоящее оформление не может брать из него итоговую цену или наличие. Запись контактной формы в console — ограничение приватности и UX для следующего ticket поддержки, а не работающая отправка обращения. Статический demo на GitHub Pages не даёт серверной границы безопасности.

**PLANNED — открытые решения:** транспорт сессии и CSRF, восстановление доступа, правила авторизации, проверка callbacks поставщика, аудит платежей/возвратов, хранение персональных данных, обработка вложений/аватара, секреты и заголовки развёртывания. Проектирование и проверка относятся к следующим implementation/security tickets. Сертификация PCI, GDPR или иная не заявляется.
